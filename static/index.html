What are we measuring?

Recall@5: the proportion of annotated evidence found in the first five results.

MRR@5: how early the first relevant result appears.

All evidence@5: whether every annotated supporting passage was retrieved.

These scores do not assess whether a generated explanation is correct.

    What was trained?

    The general English DistilBERT base model was adapted to three financial sentiment classes. Low-rank attention adapters and the classification head receive gradient updates; the base pretrained weights remain frozen.

    The baseline uses TF-IDF features and class-balanced logistic regression. A majority-class predictor provides a minimal reference. Calibration temperature is chosen using validation data only.

    How was it evaluated?

    Financial PhraseBank’s all-agreement subset has human-assigned positive, neutral and negative labels. Exact duplicates are removed; similar sentence templates are grouped before train/validation/test splitting.

    Groups do not establish event or company separation. The dataset has no usable publication timestamps for chronological evaluation. Filing paragraphs differ from the news sentences used in training.

    Dataset: CC BY-NC-SA 3.0. This portfolio application uses it for noncommercial research.

    What is actually trained?

    The reranker is a supervised logistic relevance classifier trained on query–passage pairs. It learns seven features: BM25 score, LSA cosine similarity, query coverage, numeric overlap, table indicator, bigram overlap and query density.

    The vector baseline uses TF-IDF reduced to 64 latent dimensions using SVD. It is a classical semantic baseline, not a neural embedding model.

    DistilBERT LoRA adapters and a sentiment classification head are trained separately on Financial PhraseBank. The answer-generating LLM is not fine-tuned. Hybrid retrieval uses reciprocal rank fusion; the reranker rescores the top 40 candidates.

    What can an answer promise?

    Evidence mode returns exact source excerpts and performs no generative inference. Optional LLM mode requires server-side credentials and explicitly requesting generation.

    Optional generated answers may only return exact quoted text, with verified source identifiers. Paraphrases are rejected. The separate calculator checks bounded arithmetic against cited numbers, but it does not determine whether the chosen rows, units or formula answer the question.

    Question screening, suspicious-passage filtering and evidence thresholds are limited defenses. The application is for local research; it is not a production banking security boundary.

    Reproducibility & separation

    All pages of a company’s report-year stay in the same split, assigned by a stable SHA-256 hash. Labels from validation and test are never used to train the reranker. Vocabulary and LSA are fitted on the searchable collection.

    The benchmark uses FinQA’s human evidence annotations. Dataset questions, answers and relevance labels are excluded from the searchable corpus.

    Privacy & operating scope

    Documents stay on the local server in evidence mode. When generation is enabled, your question and selected excerpts are sent to OpenAI.

    Query caches are bounded and in memory. Audit records store question hashes, evidence IDs and outcomes. Uploaded documents are persisted in the runtime directory.

    Bind to loopback. Public deployment requires authentication, tenant isolation, request limits and a dedicated security review.
